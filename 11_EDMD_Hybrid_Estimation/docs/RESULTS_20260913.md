# EDMD implementation results — 13 September 2026

Version 0.2 implements detailed forecast diagnostics, optional causal correction weighting, and explicit reversal, load-step and changed-controller scenarios. The MATLAB implementation is complete and all **66 automated checks passed**. The weighting experiment improved nominal accuracy substantially, but sacrificed accuracy under mismatch. It remains an optional research variant.

This is the historical version 0.2 implementation report. The subsequent [version 0.2.1 verification review](VERIFICATION_AND_VALIDATION.md) expands the suite to 74 tests, fixes nondefault warmup and replay boundaries, and reproduces these numerical results.

Larry Anderson — **Research collaborator and technical adviser**.

## Changes implemented

| Addition | What it enables |
|---|---|
| Endpoint records and paired event summaries | Inspect signed bias, error spread, tail errors, failures and behavior near actual velocity reversals. Every method uses matching forecast origins. |
| Singular-spectrum and ridge diagnostics | Inspect retained directions, conditioning and regularization, with the exact constant coordinate identified separately. |
| Recursive feature diagnostics | Separate one-step error from inconsistency between propagated quadratic features and a diagnostic re-lift. The re-lift never changes predictions. |
| Optional correction weighting | Choose a correction using only completed prediction errors and observed history. Record the chosen weight and reason; hold it fixed throughout the forecast. |
| Additional scenario generator options | Exercise explicit motion reversals, mechanical load steps and altered acquisition-controller gains. |
| Separate diagnostic and correction runners | Reproduce the original benchmark, select the optional rule on development validation, and evaluate it on separately seeded trajectories. |

The original fitted models, original experiment files and replay default pointer are preserved. The added weighting rule is not connected to the robot's controller or protection logic.

Weighted EDMD reduced nominal error by **95.8% relative to unweighted EDMD**, while remaining slightly above physics. It used physics alone at **98.67% of nominal forecast origins**. Under the larger mismatch conditions, the unweighted learned methods were more accurate. The weighted EDMD rule used physics alone at **28.36% of stress origins** and **44.66% of changed-controller origins**. Zero weight also occurs while the required historical window is unavailable; an origin's recorded reason distinguishes that from a model-domain or accuracy decision.

The chosen rule therefore addresses a specific problem—unnecessary correction when physics already works well—with a substantial accuracy tradeoff elsewhere. It is not a demonstrated universal model-selection rule. Linear and quadratic versions remain closely comparable. The small EDMD advantage in one added scenario does not establish a reliable nonlinear benefit.

Both learned models selected candidate 10: a **250-sample lookback**, **25% minimum historical one-step improvement**, candidate weights **0, 0.25, 0.5 and 1**, and the declared training-domain margin. Selection used only the original 12 development-validation trajectories. Nominal validation RMSE had to be within **0.1 encoder count** of physics. That allowance is an explicit research screen, not an established robot requirement.

The models and rules were frozen before first generating the 52 evaluation trajectories. A later reporting fix reran the same protocol without changing the selected rules: candidate scores, endpoint predictions, per-run results, summary results and paired comparisons were byte-identical. Those repetitions demonstrate reproducibility and are not additional unseen evidence. No tuning was performed using the new results.

## What the diagnostics established

The original benchmark's **102,400 endpoint records** were generated, with matching per-run truth RMSE and failure counts relative to the original saved benchmark. Maximum RMSE difference was **5 × 10^-16 radians**. The audit compares saved per-run metrics; the original study did not store endpoint records to compare individually.

1. **Nominal long-horizon error is mostly varying error, not constant bias.** At 250 ms, original EDMD mean trajectory RMSE was 2.66669°, centered RMS 2.63838°, and mean absolute trajectory bias 0.307273°. Squared trajectory biases account for about 2.1% of nominal MSE. The remaining variation is not necessarily random noise.
2. **The fitted affine blocks have no eigenvalues outside the unit circle.** Their spectral radii are approximately 0.997308 for linear and 0.997554 for EDMD. Full spectral radius one comes from the exact constant coordinate. This does not certify the driven or coupled observer forecast.
3. **Ridge heavily suppresses weak directions.** All 7 linear and 22 EDMD regressor directions are formally retained, but the weakest EDMD direction's ridge filter is about 3.81 × 10^-6. A large raw condition number alone does not demonstrate a noise-amplification mechanism.
4. **Quadratic features become inconsistent during recursion.** Nominal relative quadratic inconsistency grows from about 4.59% at 1 ms to 123.81% at 250 ms. This compares propagated features with a re-lift of predicted history, not true future history. The linear model has almost the same forecast deterioration without quadratic coordinates, so this finding does not establish the sole cause.

These findings support measuring forecast behavior directly before adding more features or constraining eigenvalues. State-informed dictionaries, disturbance-estimating observers and scaled coupled sensitivity analysis remain future experiments.

## Verification and evidence boundaries

- **66/66 automated tests passed** in MATLAB R2026a with Control System Toolbox. Coverage includes input timing, delayed histories, future-data isolation, weighting, numerical failure retention, event pairing, model diagnostics, generator integration and replay compatibility.
- The new study scored **199,680 endpoints**: 52 trajectories × 6 methods × 5 horizons × 128 origins. No applied forecast or raw learned candidate failed numerically in this run.
- Horizons are 1, 20, 50, 100 and 250 ms. Every method receives the same recorded future voltage. These are conditional forecast tests on hypothetical healthy-data simulations.
- Default origins begin at 200 ms. Startup is not covered. Reversal summaries use true velocity offline; load transition metadata is retained, but separate load-event summaries are not implemented.
- The changed-controller scenario combines stress parameters, separate seeds and 75% controller gains. Its comparison with the nonlinear-transient scenario does not isolate controller-gain effects.
- Overlapping origins are not independent trials. Use the trajectory-level paired tables for comparisons. This run does not establish improved hardware behavior, EMI recovery or closed-loop control.
